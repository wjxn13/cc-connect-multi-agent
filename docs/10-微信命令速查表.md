# 10 · 微信命令速查表

> 来源：`core/engine.go` 的 `builtinCommands`（命令名与别名）+ `privilegedCommands`（需管理员的那些），
> 语义逐条读过实现。**不是凭印象列的** —— 对不上源码的命令一律没收进来。
> 本机的实际授权与表现见下面「本机现状」。

---

## 0. 先知道三件事，不然会懵

### ① 斜杠命令会**同时发给全部 agent**（已实测）

L1 关卡对以 `/` 开头的消息**一律放行**（对所有 project 都放），所以一条 `/status` 会进三个 agent，
你会收到**三条回复**。日志实证（2026-09-20）：

```
11:37:32  audit: command_executed  project=my-project    command=new
11:37:33  audit: command_executed  project=my-workbuddy  command=new
11:37:44  audit: command_executed  project=my-dsh        command=new
```

而且**没有任何语法能把命令限定给单个 agent**：`handleCommand` 只在
`strings.HasPrefix(content, "/")` 时才触发 —— 写成 `@dsh /stop` 就不是命令了，
会被当成普通消息（三个 agent 里只有 dsh 收到，但它会把「@dsh /stop」当话去答）。

### ② 特权命令只有 Claude 能用

`admin_from` 只配在 `my-project`。`my-dsh` / `my-workbuddy` **没配** —— 而 `admin_from` 为空是
**fail-closed（一律拒绝）**，所以特权命令在这两个 project 上会回：

> 🔒 命令 `/shell` 需要管理员权限。请在配置中设置 `admin_from` 来授权用户。

（也就是说：你发一条 `/restart`，会收到 1 条真结果 + 2 条「需要管理员权限」。）

### ③ 微信不支持卡片 → 一切都降级成纯文本

`platform/weixin/` 里没有任何卡片代码，所以带按钮的 `/help` `/model` `/list` 在微信里
都是 `Card.RenderText()` 的一段文字。**能用，只是没有按钮可点**，需要手动打命令。

## 1. 会话管理（`/help` 的 session 组）

| 命令 | 别名 | 作用 |
|---|---|---|
| `/stop` | — | **只打断**当前正在跑的任务。保留会话与 `AgentSessionID`，下一条消息自动接着聊 |
| `/cancel` | — | 打断 **+ 清空历史 + 开新会话**。等于 stop + new，**不可逆**（历史清掉就没了） |
| `/new` | — | 开新会话（旧会话仍在，可用 `/switch` 回去） |
| `/list` | `/sessions` | 列会话，**带序号**（后续 `/switch`、`/delete` 都用这个序号） |
| `/switch <序号\|id前缀\|名字>` | — | 切到某个会话 |
| `/current` | — | 看当前在哪个会话 |
| `/history` | — | 看当前会话的历史 |
| `/name <名字>` | `/rename` | 给当前会话改名 |
| `/search <关键词>` | `/find` | 按**会话名或消息内容**搜历史会话 |
| `/delete <序号>` | `/del` `/rm` | 删会话。支持 `/delete 1,2,3`、`/delete 3-7`、`/delete 1,3-5,8` |

**`/stop` 与 `/cancel` 的区别是这套里最容易记混的**：
`/stop` = 「停一下，重说」；`/cancel` = 「这条线废了，重新开始」。

回复长这样：`/stop` → `⏹ 执行已停止。` 或 `没有正在执行的任务。`；`/cancel` → `会话已取消。可以继续新的对话。`

## 6. ⚠️ 需要管理员 —— 本机只有 Claude 能用

`privilegedCommands` 一共 7 个（源码 `core/engine.go` 的 `privilegedCommands` 表）：

| 命令 | 别名 | 作用 |
|---|---|---|
| `/shell [--timeout <秒>] <命令>` | `/sh` `/exec` `/run` | 执行 shell。例：`/shell ls -la`、`/shell --timeout 300 npm install` |
| `!<命令>` | — | `/shell` 的快捷方式：`!ls -la` 等价于 `/shell ls -la`（需管理员的判断与 `/shell` 完全一样） |
| `/dir` | `/cd` `/chdir` `/workdir` | 工作目录 |
| `/show` | — | 展示文件 |
| `/web` | — | Web 管理后台 |
| `/diff` | — | 看改动 |
| `/restart` | — | 重启服务 |
| `/upgrade` | `/update` | 升级 |

> `!` 的坑：它**排在权限应答处理之后**，所以 `!yes` 不会被当成 shell 命令抢走权限应答。
> 另外带图片的消息不会被当成 `!` 命令。

## 7. 本机最顺手的几条组合

| 场景 | 发什么 |
|---|---|
| 跑歪了，想接着聊 | `/stop`，然后重说一句 |
| 这条线整个废了 | `/cancel`（注意：历史会清掉） |
| 觉得变慢了 / 上下文太长 | `/compress` |
| 长任务跑着，想补一句 | `/ps 先别管前端` |
| 想找回上周那次对话 | `/list` → `/switch 3`（或直接 `/search 关键词`） |
| 群里刷屏太多 | `/quiet`（切到 quiet，不再播报思考和工具调用） |
| 想知道自己的 user id | `/whoami` |
| 服务行为不对 | `/status` → `/doctor` → `/config` |

## 8. 三条坑

1. **拼错的斜杠命令会当成普通消息发给全部 agent**。源码注释写得很直白：
   `// Unrecognized slash command — fall through to agent as normal message`。
   加上 L1 对 `/` 的豁免，`/stp` 这种手滑会被三个 agent 各当成一个提问去作答（**三个都烧 token**）。
   这是已知缺口（详见 `docs/07` 第五节），当前没修。
2. **`/cancel` 是破坏性的**（清历史 + 废掉会话 ID），只想打断用 `/stop`。
3. **`/delete` 在微信里没有按钮**，必须带参数；不带参数只会回用法说明。
