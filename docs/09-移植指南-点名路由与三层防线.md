## 2. `core/engine.go` 的插入位置怎么找

**不背行号，认锚点。** 四处：

### ① 关卡本体（新增函数，集中放在一起）

搜 **`mentionGateTargets`**。它周围一圈依次是：

```
mentionGateTargets      两段式判定（句首段优先 → 位置判定 → default）
mentionGateDrop         薄包装，给单 owner 的调用点用
scanLeadingMentionRun   句首点名段解析（引擎侧）
isMentionSeparator      分隔符白名单
mentionGateBlocked      关卡本体（用它的入口：cron / timer / heartbeat / webhook）
rememberAddressees      记下这一组被点名的 project
mentionsSelf            委托给 mentionGateTargets，避免两套规则打架
bareMediaMessage        「有附件、无文字」
mediaRouteOwner         纯媒体归属（粘性 → media_default → default）
mentionGateBlocksMessage 实时聊天专用入口
```

### ② 实时聊天入口（最容易找到的那个）

函数 **`handleMessage()`**。找注释 **`// Multi-workspace resolution`**，**在它紧上面**插：

```go
if e.mentionGateBlocksMessage(msg) {
    return
}
```

必须落在**违禁词检查之后**（那块以 `message blocked by banned word` 结尾、`return` 收尾），这样别名解析和 `ExtraContent` 合并都已完成，判的是最终内容。

### ③ 四个合成投递入口

见 §3 的表。它们全都在注释里带 **`bypass handleMessage`** 或 **`synthetic message`** 字样 —— 搜这两个词能一把捞出来。

### ④ 出站身份前缀（`agent_label`）

搜 **`agentLabel`**。施加点在引擎的**两个发送咽喉**，所以回复、报错、排队提示都会带前缀；长文本被平台切成多条时**只有第一块**带。

## 3. 五个投递入口 —— 少一个就漏一类流量

| # | 流量 | 函数 | 调哪个入口 | 备注 |
|---|---|---|---|---|
| 1 | 实时聊天 | `core/engine.go` `handleMessage()` | `mentionGateBlocksMessage` | 唯一需要「懂空文本 = 图片」的入口 |
| 2 | **webhook** | **`core/webhook.go` `executePrompt()`** | `mentionGateBlocked` | **最容易漏，见下** |
| 3 | cron | `core/engine.go` `ExecuteCronJob()` | `mentionGateBlocked` | 带 `!job.IsShellJob() &&` 前缀：shell job 豁免 |
| 4 | timer | `core/engine.go` `ExecuteTimerJob()` | `mentionGateBlocked` | 同上豁免 |
| 5 | heartbeat | `core/engine.go` `ExecuteHeartbeat()` | `mentionGateBlocked` | |

### 为什么 `webhook.go` 那个不能漏

`executePrompt()` 把一个合成消息**直接塞进处理循环**，根本不经过 `handleMessage()`。只在 `handleMessage()` 里加关卡的话，webhook 流量会**整条绕过**关卡 —— 表现是「微信侧悄无声息，但 token 在花」，因为会话、通知、agent 进程全都正常跑了一遍。

```go
func (ws *WebhookServer) executePrompt(engine *Engine, sessionKey, prompt string, silent bool, event string) {
	// Cross-agent mention gate — a webhook injects a synthetic message straight
	// into the processing loop, bypassing handleMessage. Check before doing any
	// work so a dropped event costs nothing (no notification, no session, no
	// agent process).
	if engine.mentionGateBlocked("webhook", prompt, sessionKey, "webhook") {
		return
	}
	...
```

### 为什么它用 `mentionGateBlocked` 而不是 `mentionGateBlocksMessage`

webhook / cron / timer / heartbeat 的 prompt 都是**人写的文字**（定时任务、定时器、心跳提示词），永远不会是「无文字纯媒体」。`mentionGateBlocksMessage` 多出来的那层（粘性 + `media_default`）对它们没有意义；用了反而会把一条正常文字误判成「待认领的图」。**只有实时聊天那条路需要它。**

## 4. 装配点有两处，别只改一处

`cmd/cc-connect/main.go`：`main()` 的项目循环里一份，`reloadConfig()` 里一份。两份的注释都写着「Kept in sync with the same block in reloadConfig()」—— 改一处就会出现「重启后生效、`/reload` 后失效」这种半生效。

```go
if self, peers, fallback, gated := mentionRoutingFor(cfg, proj.Name); gated {
    engine.SetMentionRouting(self, peers, fallback)
    engine.SetMentionSticky(mentionStickyForProcess)      // 进程级单例，别每个 project 各建一个
    engine.SetMentionMediaTarget(mentionMediaTargetFor(cfg))
} else {
    engine.SetMentionRouting(nil, nil, "")                // 空 self = 关卡关闭 = 回到加功能之前
}
```

`self` 传空切片即等于「这个 project 不受关卡保护」，这是整个特性 **opt-in / 可一键回退**的关键 —— 任何一层出问题时，把 `[[mention_agents]]` 条目去掉就回到原状。

## 5. 扩缩容：增删一个 agent 行不行

**结论：纯配置动作，零代码改动。** 关卡是**按名字索引**的 —— `mentionRoutingFor()` 每次都从 `[[mention_agents]]` 现有条目**现算** peer 表；代码里不存对端列表、不存数量、不存序号。
（实测见 `config/mention_agents_scale_test.go`：1 / 2 / 3 / 4 / 6 个 agent、以及整表去掉，全部通过校验。）

| 动作 | 结果 |
|---|---|
| 加 `[[projects]]`，暂时不加 `[[mention_agents]]` | ✅ 合法。该 project 关卡自动关闭，行为回到加功能之前 —— 可以分两步上 |
| 加一个 agent（两表都加） | ✅ 别人的 peer 表**自动**多出它，不用改任何代码 |
| 删一个 agent（删 `[[mention_agents]]` 条目） | ✅ 合法，服务照常起。但见下面「代价」 |
| `project =` 写错 | ❌ 启动报错 `does not match any [[projects]] name` |
| 两个 project 认领同一别名 | ❌ 启动报错 `claimed by both` |
| 同一 project 声明两次 | ❌ 启动报错 `declared more than once` |
| 条目一个别名都不给 | ❌ 启动报错 `needs at least one non-empty alias` |
| `default` 写别的值 | ❌ 启动报错 `default must be "answer" or "silent"` |
| 几个 agent 都设 `default = "answer"` | ✅ 无数量限制（不要求「恰好一个」） |
| `media_default = true` 设两处 | ⚠️ **不报错**。`mentionMediaTargetFor()` 只认文件顺序第一个，第二个被静默忽略 |

### 删 agent 的代价（必看）

删掉之后，用户若还照旧写 `@那个名字`，这个别名就成了**未知别名**，会掉进两层的缝里：

- **L1**：未知别名「不归我路由」→ **放行给所有人**（fail-open，设计如此）
- **L3**：规则第 5 条「无法确定点名了谁 → NO_REPLY」→ **全员闭嘴**

净效果 = **所有人都沉默，但 token 花了**。

**省事的解法：让别名搬家，而不是消失。** 别名列表本来就支持多个 —— 把旧别名挂到承接它的那个 project 上即可：

```toml
[[mention_agents]]
project = "my-workbuddy"
aliases  = ["@wb", "@workbuddy", "@dsh"]   # 旧名 @dsh 迁到这里，历史习惯不用改
```

删 `[[mention_agents]]` 条目时，`[[projects]]` 条目**留着也不碍事**，只是那个 project 不再受关卡保护（回到「所有消息都进、全靠 NO_REPLY 闭嘴」的旧行为）。

## 6. 一小时重做顺序

1. **拿料**：上游源码 + `patches/0001`–`0011`。`git am` 应用（A 组对上游 `main` 需 rebase，见 `patches/README.md`）。
2. **编译**：版本串**必须含 `1.3.4`**，否则 npm 全局启动器会判定版本不符、自动重装并把自编译 exe 覆盖掉。
   `-ldflags "-s -w -X main.version=1.3.4+mention -X main.commit=<sha> -X main.buildTime=<ts>"`。
   Windows 上用 `D:/...` 风格路径 —— `-o /d/...` 会被原生工具**静默**写成 `D:\d\...`（退出码 0，产物找不到）。

4. **L2 钩子**：`hooks/l2-userpromptsubmit.js` → `~/.cc-connect/hooks/`，再按 `hooks/README.md` 往三家注册。跑 `python scripts/l2_hook_tests.py`（46 用例）。钩子是**每条消息重新加载**的，改完即生效、**不用重启**。

6. **端到端验收**（四条就够）：
